My Interactive Learning Experience Design System

How I design interactive HTML learning experiences

This is the practical system I have developed through curriculum leadership, software engineering, classroom instruction, visual design, and hands-on prototyping. I use it to turn learning goals into experiences that are clear, engaging, accessible, technically reusable, and grounded in evidence of mastery.

The central idea

I treat visual design and learning architecture as one connected system.

I created this approach by combining what I have learned from curriculum development, technical program leadership, software engineering, game and interaction design, teaching, and watching real learners use digital experiences. It preserves the speed and creativity of visual exploration while adding the instructional structure, technical planning, and testing needed to make the final experience work in practice.

JR

I use this as a practical working system, not a rigid linear methodology. I move backward and forward whenever a prototype, learner response, technical constraint, or visual test reveals a better direction.

My decision filter

Will this help students learn?

01

Phase one · Define the learning experience

I start with the learning—not the layout.

Before I choose colors, collect references, or open a design tool, I define what success means for the learner. This prevents the interface from becoming attractive but instructionally empty.

My design triangle
Learning objective+Learner action+Evidence of mastery

If one side is weak, the experience will feel disconnected.

1

Establish the learning goal

I define what students should know or be able to do by the end of the experience, along with the conditions in which they must demonstrate it.

  • Target learner and grade level
  • Learning objective
  • Academic standards
  • Expected session length
  • Prior knowledge
  • Evidence of mastery
  • Required accessibility level
  • Device and browser requirements
Example objective

Students will identify three indicators of a phishing email and correctly decide how to respond.

2

Select the experience format

I choose the interaction model that best reveals the target knowledge or skill. I do not add a game format merely to make the lesson feel more entertaining; the format must make the learning more visible, authentic, or memorable.

Guided simulationBranching scenarioInteractive investigationDecision-making challengePuzzle or escape roomDigital labRole-playing experienceCard-sorting activityNarrative adventureBuild-and-test challenge
3

Define the core experience loop

I identify what the learner repeatedly does. This loop creates the rhythm of the experience, limits unnecessary interaction patterns, and makes the learner's thinking visible enough to assess.

Example core loop
Observe→Investigate→Decide→Feedback→Advance

For a phishing investigation: Open message → Inspect clues → Mark evidence → Choose response → See consequences.

My default rule is to keep each screen centered on one meaningful task or decision. Complexity can grow across the experience without crowding every moment.

02

Phase two · Plan the content and flow

I map the learner journey before I style it.

I establish the complete experience path, inventory the real content, and define exactly how feedback and mastery will work before the interface depends on incomplete placeholders.

4

Create the experience map

I map every screen and meaningful path before I design the visuals. This helps me identify missing transitions, dead ends, overloaded screens, and decisions that do not actually change the experience.

  • Entry or mission briefing
  • Instructions
  • Primary challenges
  • Feedback moments
  • Optional clues or help
  • Incorrect-answer recovery
  • Assessment
  • Completion screen
  • Replay or next-step options
  • Branch points and reconnection points
5

Create a content inventory

I list everything the experience needs before interface decisions become dependent on placeholder content. Realistic content often changes the space, hierarchy, pacing, and interaction support the design requires.

Content

What the learner sees

Instructions, dialogue, questions, answers, images, characters, emails, documents, evidence, clues, and feedback messages.

System states

What the interface must support

Sounds, hints, selected states, scores, badges, progress indicators, errors, retries, and completion messages.

6

Define assessment and feedback

I define how the experience will measure learning and how each action will help learners improve. Feedback is part of the instruction, not a decorative message added after the interaction.

  • Actions that earn points
  • Retry rules
  • Hint penalties or support
  • Mastery threshold
  • Action-level feedback
  • Final results communication
My feedback standard

Explain why an action was correct or incorrect. Do not stop at “Correct” or “Try again.”

03

Phase three · Establish the visual direction

I start loose, then make the visual direction progressively more specific.

I use rapid reference gathering, deliberate visual distillation, representative mockups, and a restrained design system to define realism, tone, hierarchy, and interaction states before complex production begins.

7

Collect references

I gather references in clear categories: interface layouts, real-world tools, characters, environments, color, typography, icons, animation, sound, and atmosphere. At this point I prioritize range and useful evidence over presentation quality.

For realistic simulations

I collect references from the actual tools learners would encounter—such as email clients, security dashboards, or messaging systems.

8

Build the mood board

I organize references in Milanote, PureRef, or Figma, but I do not treat the first board as a final answer. It is a fast visual hypothesis that helps me identify emotional tone, realism, age appropriateness, visual density, interface style, character style, lighting, and motion.

“Sophisticated enough for high school students. Realistic interfaces with stylized narrative elements. One important decision per screen.”

My fast mood-board iteration loop

I use the first board as raw material—not as a finished visual strategy.

The goal is not to make the first mood board beautiful. The goal is to externalize possibilities quickly, discover what the experience actually needs, and create enough evidence to make better visual decisions.

01

Slap together a mood board

I collect anything that captures a useful quality: a believable email layout, an interesting lighting treatment, a character silhouette, a color relationship, a transition, or a sense of atmosphere. I allow contradictions at this stage because contrast helps me see the available directions.

Output: a broad, imperfect reference field.
02

Narrow to the must-haves

Using the learning goal and experience requirements as the filter, I identify three to five visual qualities the design cannot lose. These might include realistic source material, mature character styling, low visual clutter, discoverable evidence, or a clear single-screen focal point.

Output: a short list of visual non-negotiables.
03

Extract a working color scheme

I sample relationships from the strongest references, then convert them into functional roles: page background, surfaces, primary action, selected evidence, warning, success, danger, and subdued information. I adjust the palette for contrast and readability rather than copying reference colors literally.

Output: a role-based, accessibility-aware palette.
04

Write the shorter visual vision

I compress the board into a one-page direction that another designer or developer could use without seeing every reference. It describes the intended feeling, realism level, density, visual hierarchy, interaction distinction, motion behavior, and what the design should avoid.

Output: a concise visual vision document.
05

Mock up representative art

I apply the direction to one demanding, representative screen—not the easiest screen. I document what supports the learning, what competes for attention, what feels too young or too corporate, what would be expensive to reproduce, and what breaks when realistic content is inserted.

Output: a test screen plus a decision log.
06

Feed the result back into the process

I use the mockup as new reference material. I revise the mood board, must-haves, palette, and visual vision, then test again. Each cycle should remove ambiguity and make the system easier to apply across the complete experience.

Output: a clearer direction with fewer unresolved choices.

My one-page visual vision

What I capture after the mood board

  • Experience statement: one sentence describing what the learner should feel and do.
  • Must-have traits: three to five qualities that define the direction.
  • Avoid list: signals that would make the experience feel childish, artificial, cluttered, or misleading.
  • Realism balance: which interfaces must be authentic and where stylization can support story or motivation.
  • Palette roles: colors assigned to actions, information, status, and assessment—not merely swatches.
  • Hierarchy rule: how the learner recognizes the current goal, available action, evidence, and feedback.
  • Motion rule: when animation explains state or direction and when it should remain absent.
  • Production constraints: reusable art, responsive behavior, asset limits, and browser performance.
What I document after each mockup

Evidence, not vague preference

Keep: What immediately supports tone, clarity, or authenticity?

Change: What competes with the task or obscures interaction?

Question: What still needs learner, stakeholder, or technical validation?

Systemize: Which successful decisions can become reusable components or rules?

Hierarchy

Direct the eye.

I use scale, contrast, spacing, and restrained motion to make the next action unmistakable.

Composition

Guide attention.

I use lighting, leading lines, gaze direction, and environmental shapes to point toward meaningful clues.

Responsiveness

Design scaling rules.

I choose a base viewport, then define minimum width, wrapping, text limits, and hotspot behavior.

Readability

Protect comprehension.

I set minimum type, contrast, line length, button size, captions, and text-on-image standards.

9

Establish the design system

Once the direction survives a representative mockup, I translate it into a restrained set of reusable rules and states. I design components before I produce an entire library of polished screens.

Design system essentials

Color roles · type scale · spacing · buttons · cards · panels · icons · focus states · motion behavior

04

Phase four · Design the interface

I prove clarity before I invest in polish.

I solve hierarchy, navigation, pacing, and recovery in grayscale before complex art makes structural changes expensive.

10

Sketch and wireframe

I create rough layouts for information hierarchy, primary actions, navigation, dialogue, evidence, progress, feedback, and accessibility controls.

My wireframe test

A screen should remain understandable without color or polished artwork.

11

Build a low-fidelity prototype

I use realistic text quantities and clickable blocks to test spacing, reading order, click count, menus, navigation, movement, decision flow, feedback timing, and smaller-screen behavior. At this stage, changing the structure should still be inexpensive.

  • Screen spacing
  • Reading order
  • Number of clicks
  • Menu behavior
  • Navigation clarity
  • Character movement
  • Decision flow
  • Feedback timing
  • Mobile and smaller screens
12

Conduct a clarity test

I ask representative users to complete the experience without verbal guidance. I observe behavior before asking for opinions because hesitation, missed information, and incorrect clicks often reveal more than preference feedback.

Clarity test

What I watch while learners work

  1. 01Where do they look first?
  2. 02What appears clickable?
  3. 03Do they understand the goal?
  4. 04Where do they hesitate?
  5. 05What information do they miss?
  6. 06Can they recover from mistakes?
  7. 07Does feedback improve the next attempt?
05

Phase five · Create the visual experience

I add atmosphere without sacrificing comprehension.

I introduce final art, motion, sound, and realism only after the experience structure is stable—and I maintain a clear distinction between what is decorative, interactive, informational, and assessed.

13

Produce the high-fidelity design

I add final typography, color, lighting, illustrations, characters, realistic interface details, environmental art, icons, transitions, sound cues, and microinteractions.

01Decorative
02Interactive
03Informational
04Assessment
14

Apply composition and hierarchy rules

Visual hierarchy

Place the primary objective first.

I use size, contrast, spacing, and motion sparingly to establish priority.

Aspect ratio

Define responsive behavior.

I choose a base design viewport—such as 1440 × 900 or 16:9—then define minimum width, panel wrapping or collapse, mobile behavior, maximum text width, and hotspot scaling rules.

Composition

Guide attention naturally.

I use lighting, contrast, gaze direction, environmental shapes, and leading lines.

Readability

Protect essential text.

I define minimum font size, line length, line spacing, contrast, button size, captions, instructions, and text-over-image rules. I do not shrink essential text merely to preserve a composition.

Hotspot rule

When clickable zones sit over background art, I keep the artwork and hotspots inside the same proportionally scaling container.

06

Phase six · Build and validate

I build a reusable learning system—not a collection of one-off pages.

I separate lesson content from interface logic whenever practical, build reusable components, and validate learning, usability, accessibility, and technical reliability together.

15

Create the HTML prototype

I build reusable components rather than treating every lesson as a separate application. A structured content layer can let the same experience engine support many lessons and scenarios.

Content-driven architecture

A JSON-based structure can keep lesson content separate from the interface and make future experiences faster to build and easier to maintain.

16

Test the complete experience

I test four core areas, then verify loading time, broken interactions, keyboard focus, scoring, retries, saved state, audio controls, and accidental refreshes.

17

Pilot and improve

I pilot with a small group of representative students and diagnose whether problems come from content, interface, instructions, or difficulty—not simply whether students liked the experience.

Completion

Completion rate, abandonment points, and time per challenge.

Performance

Incorrect-answer patterns, assessment results, and retry behavior.

Support

Hint usage, feedback effectiveness, and teacher intervention.

Perception

Student confidence, comments, and explanations of their choices.

07

Phase seven · Package the work for reuse

I preserve the reasoning—not only the finished screens.

A reusable system includes the decisions, assets, logic, and evidence needed to maintain the experience, hand it off, adapt it, and begin the next project from a stronger foundation.

18

Document the completed experience

I save the complete design record so the experience can be evaluated and extended without recreating the reasoning from scratch.

  • Experience map
  • Script and content
  • Mood board
  • Visual vision document
  • Design system
  • Component inventory
  • Assessment logic
  • Accessibility checklist
  • Testing results
  • Decision log
  • Final source files

The compact version of how I work

Define → Select → Map → Assess → Reference → Distill → Mock up → Prototype → Validate → Improve

The process is intentionally iterative. A visual test can send me back to the mood board. A learner test can change the content map. A technical constraint can reshape the interaction model. The system works because every step stays connected to the learning triangle.
